Lab — Digit Classifier

Goal: Build and train a small neural network that reads handwritten digits — your first classifier, and your first hands-on look at the neuron stack from this module's lesson: a weighted sum, an activation function, layered until the network can tell a 3 from an 8.

Time: ~20 minutes hands-on, plus a one-time TensorFlow install that can take a few minutes depending on your connection. Prerequisites: none beyond what Step 1 sets up. This module needs its own environment — you are not reusing Module 3's scikit-learn setup.

Step 1 — Create this module's own venv​

Every module's lab lives in its own folder under labs/ in the course repo, with its own dependencies. Module 4 needs one new package Module 3 didn't: TensorFlow, which bundles Keras, the library you'll use to build the network. From the root of the course repo (where you cloned aiml-foundations-labs):

cd labs/m4
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

Run the script:

python3 mnist_digit_classifier.py

Step 3 — Read the lines that matter​

Open the file and look at what actually ran:

cat mnist_digit_classifier.py

Everything in this script maps onto a concept from the lesson:

StepLineLesson concept
1keras.datasets.mnist.load_data()Load the data — 70,000 labeled digit images
2X_train / 255.0Feature prep — scale raw pixels into small, consistent numbers
3Dense(128, activation="relu")A layer of neurons — weighted sum + activation, stacked
3Dense(10, activation="softmax")The output layer — one logit per digit, squashed into probabilities
4model.compile(...)How "wrong" gets measured, and how the weights get nudged
5model.fit(...)Training — the network adjusts its weights over a few epochs
6model.evaluate(...)Evaluation — the honest score, on data the network never trained on
7model.predict(...)Inference — same weights, applied to one new image, no learning happening

Notice the two Dense layers are exactly the lesson's neuron, twice: a weighted sum of the previous layer's outputs, passed through an activation function. The first layer's 128 neurons each look for some pattern in the raw pixels; the second layer's 10 neurons each produce a logit for one digit, and softmax turns those ten logits into a probability distribution — the same squashing step logistic regression's sigmoid does, generalized from two outcomes to ten.

Try it: shrink the hidden layer

Change Dense(128, activation="relu") to Dense(4, activation="relu") and re-run. With only four neurons in the hidden layer, the network has far less room to represent the different ways a digit can be drawn, and test accuracy drops noticeably. This is the lesson's "more neurons, more capacity" claim, made visible as a real number. Put 128 back before moving on.

Common Pitfalls​

TensorFlow install takes a few minutes and a few hundred MB

This isn't a stuck terminal — TensorFlow is a large package with several native dependencies. pip install -r requirements.txt genuinely takes longer than the installs in earlier modules. Let it finish; there's nothing to interrupt or retry.

SSLCertVerificationError when MNIST downloads

On some macOS setups (notably python.org-installed Python, which doesn't link the system CA bundle), the first load_data() call can fail with an SSL certificate error while trying to download MNIST. Fix: point Python at the certifi package's bundle for that one run — SSL_CERT_FILE=$(python3 -m certifi) python3 mnist_digit_classifier.py. Once the dataset downloads (cached under ~/.keras/datasets/), every later run works with the plain command — you only need the workaround once.

Could not find cuda drivers / GPU-related warnings

TensorFlow checks for a GPU on startup and prints a warning if it doesn't find one. On a CPU-only laptop, this is expected and harmless — training three epochs on MNIST is fast enough on CPU alone that you don't need a GPU for this lab. The warning is informational, not an error; if the script goes on to print training progress and a test accuracy, it worked.

ValueError about input shape when skipping Flatten

MNIST images arrive as 28×28 grids, but a Dense layer expects a flat list of numbers, not a 2D grid. keras.layers.Flatten(input_shape=(28, 28)) is what reshapes each image into 784 numbers before the first Dense layer ever sees it. Drop that layer, or feed a Dense layer a raw image directly, and you'll get a shape-mismatch error naming the dimensions that didn't line up.

Loss going down does not automatically mean accuracy is good

Watch the per-epoch output in Step 2: loss and accuracy are two different numbers. Loss can keep dropping while accuracy stays mediocre, especially with too few epochs or too small a network. Always check the Test accuracy line specifically — loss is what the optimizer is minimizing internally, accuracy is the number that tells you whether the model is actually useful.

ModuleNotFoundError: No module named 'tensorflow'

Check your venv is active — you should see (.venv) in your prompt; if not, source .venv/bin/activate again, from inside labs/m4. TensorFlow is a Module 4-only dependency — Module 3's venv doesn't have it, and vice versa, because each module keeps its own isolated environment.

Teardown​

deactivate

There's nothing else to clean up — no containers, no cloud resources, no background processes. The cached MNIST data under ~/.keras/datasets/ is harmless to leave in place; later modules don't depend on it, but removing it just means the next load_data() call re-downloads it.
