Deep Dive — Inside the Neuron, and Two Toolbox Extras

The lab called Dense(128, activation="relu") and a working layer of neurons came back, instantly, and trained itself over three epochs without you ever seeing a single weight. Part 2 opens that layer up: the exact arithmetic one neuron runs, how that arithmetic chains forward through a tiny network, and how the error signal that trains it actually flows backward, neuron by neuron. Then it closes out the toolbox with two algorithms the lesson only named — SVMs and the mechanism inside boosting — worth knowing by more than name, because you'll meet both again in review meetings and vendor comparisons long after this course ends.

Where this picks up

This page needs nothing from the lab's TensorFlow venv — the script below is plain Python 3 from the standard library (just math), no packages, no network calls, nothing to configure. Run it from anywhere; re-running is always safe.

cd labs/m4

1 — The math inside one neuron​

Take the lab's first hidden neuron and do its arithmetic by hand, on one input. Say the neuron receives two inputs, x1 = 0.5 and x2 = 0.8, and it has learned two weights and a bias: w1 = 0.9, w2 = -0.3, b = 0.1.

A neuron does exactly two things to those numbers:

  1. Weighted sum: multiply each input by its weight, add them, add the bias. z = (0.9 × 0.5) + (-0.3 × 0.8) + 0.1 = 0.45 - 0.24 + 0.1 = 0.31
  2. Activation function: squash that raw sum, z, through a fixed nonlinear function. The lab used ReLU for hidden neurons (z if positive, else 0) and sigmoid for a two-outcome probability. Run 0.31 through sigmoid: a = 1 / (1 + e^-0.31) ≈ 0.5769.

That's it. That a = 0.5769 is the one number this neuron hands to whatever reads its output next — the next layer, or the loss function if it's the last layer. Everything a neural network does, at any size, is this same two-step calculation, run millions or billions of times in parallel and chained across layers.

2 — A forward pass through a tiny network​

Extend that one neuron into the smallest network that still shows real structure: two inputs, two hidden neurons, one output neuron.

Run the hand-written version — the same two inputs from Section 1, feeding a 2-neuron hidden layer and one output neuron, followed by one full backprop step (Section 3 reads the second half of this same output):

python3 neuron_math.py

Expected output

--- forward pass ---
hidden neuron 1: z=0.3100 a=0.5769
hidden neuron 2: z=0.5400 a=0.6318
output neuron:   z=-0.0983 a=0.4754
loss before backprop: 0.2752

--- one backprop step ---
output-layer gradients: w_h1_out=-0.0755 w_h2_out=-0.0827 b_out=-0.1308
hidden-layer error signal: d_h1=-0.0128 d_h2=0.0183

--- forward pass after the update ---
output after update: 0.5042
loss after backprop: 0.2459

Compare the script's hidden neuron 1: z=0.3100 a=0.5769 line to the arithmetic in Section 1 — same numbers, because it's the same neuron. Hidden neuron 2 runs the identical two steps with its own weights, and the output neuron does it a third time, except its two inputs are the activations of the hidden neurons instead of raw x1/x2. That's the entire meaning of "forward pass": one neuron's output becomes the next neuron's input, layer by layer, until a final number comes out the other end.

3 — Backprop intuition: how the error flows backward​

The lab's model.fit() call did this next part for you, three epochs' worth, without printing a single number. Here it is, once, by hand.

Analogy: picture a small team that shipped a wrong number in a report. The manager traces it backward: which team member's section fed that number, and how much did their section actually move the final total? The people whose sections mattered more get more of the correction; the ones who barely touched the final number get told to leave their part alone. That's backpropagation — pushing the blame for a wrong answer backward through the network, proportional to how much each weight actually contributed to it.

Mechanically, three things happen, in this order:

  1. Measure the error at the output. The network's answer, a_out, is compared to the target it should have produced. error_out = a_out - target.
  2. Convert error into a gradient, one layer at a time. At each neuron, the error gets multiplied by that neuron's own activation derivative (how sensitive its output is to a small change in its input) — this is d_out, then d_h1 and d_h2 in the script's second block. This is the "how much did you actually contribute" step: a neuron whose activation was near-flat at this point barely moves the error backward through it, no matter how large its weight is.
  3. Update every weight a small step opposite its gradient. Same update rule from Module 3's Deep Dive — weight -= learning_rate × gradient — just applied to every weight in every layer, not two numbers on a line.

Look at the script's own two loss lines: loss before backprop and loss after backprop. One call to fit() in Keras runs this exact three-step sequence, once per training example (or batch of examples), thousands of times over — the loss line dropping, epoch after epoch, in the lab's training output is this same shrinking number, just measured every few thousand steps instead of after just one.

Why this stays hidden in practice

You will almost never write backprop by hand at work — Keras, PyTorch, and every other framework compute it automatically via autodiff, walking the same chain of derivatives this script wrote out manually. Knowing the mechanism is what lets you read a training log and recognize a real problem (a gradient that has gone to zero, or exploded) instead of treating the framework as a black box that occasionally misbehaves.

4 — Two more toolbox extras: SVM and what boosting is really doing​

The lesson named these; here's the mechanism.

Analogy: imagine drawing the widest possible road between two neighborhoods on a map, so that cars starting from either side never wander into the other neighborhood's blocks by mistake. A support vector machine (SVM) finds exactly that: the decision boundary between two classes that maximizes the margin, the empty gap, on either side. Only the points closest to that boundary — the support vectors — actually determine where it sits; move any other point and the boundary doesn't budge. SVMs can also bend that boundary into a curve, using a trick called the kernel trick: it computes what the data would look like if projected into a higher-dimensional space where a straight boundary works, without ever actually building that higher-dimensional data. Why you still meet SVMs: on a smaller, cleanly-separable tabular dataset, an SVM trains in seconds with a mathematically provable margin, no GPU required — a neural network thrown at the same small dataset usually just relearns the same boundary, slower.

Boosting, mechanically, is doing something more specific than "a chain of editors." Each new tree in a gradient-boosted model isn't trained on the original labels — it's trained to predict the residual, the gap between what the model has predicted so far and the true label. Fit a tree to those residuals, add its (scaled-down) predictions to the running total, and the total gets a little closer to the truth; repeat. That is gradient descent — measure the error, take a step that reduces it, repeat — running in "function space" instead of "weight space": instead of nudging numbers inside one model, each boosting round adds an entirely new tree as the "step." Add enough rounds, and the model starts fitting the residual noise instead of the residual signal — the exact overfitting failure from Module 3, showing up one tree at a time instead of one weight at a time.

Where you will use this
  • A gradient near zero, or a loss that suddenly jumps to NaN, has a specific, traceable cause — a neuron stuck flat (activation saturated) or a learning rate too large for the step it's taking. Use it when: you're staring at a training log with a stalled or exploded loss and need to know whether to check the learning rate, the activation function, or the data, instead of just restarting the run and hoping.
  • An SVM is still the right first call on a small, clean, tabular dataset with no GPU budget. Use it when: a proof-of-concept needs a defensible decision boundary today, on a few thousand rows, and spinning up a neural network would cost more setup time than the problem justifies.
  • Gradient boosting's n_estimators (how many trees) and learning_rate (how big a step each tree takes) directly control overfitting, because each tree is one more residual-fitting step. Use it when: you're tuning a boosted model in production and validation accuracy starts dropping as you add more trees — that's the model fitting the residual noise, and the fix is fewer estimators or a smaller learning rate, not more data.
