Lab — Map the Agent Ecosystem

Goal: Prove you can look past a product's name and place it correctly on the four-layer agent stack from the lesson — model, tools & MCP, memory, orchestration — including the one item on the list that deliberately spans more than one layer.

Time: ~15 minutes Prerequisites: the lesson, and ideally Module 6's lab completed at least once — several items on this list are pulled directly from the agent you built there. This lab is reading and writing, not code. If you haven't cloned the labs repo yet, see setup/environment first.

Step 1 — Place 12 items on the stack​

From the root of the course repo, open the mapping exercise:

cd labs/m13
cat stack-map.md

You'll find 12 items — real tools, products, and pieces of your own Module 6 agent. Each one belongs to exactly one of four layers: Model, Tools & MCP, Memory, Orchestration — except one, which genuinely belongs to more than one at once. Work through all 12 before you look at the answer key, and pay attention to the ones pulled straight from agent.py and tools.py — you already built the thing being asked about, you're just naming the layer it lives on.

Once you've written down your 12 answers, scroll to the Answer key section at the bottom of the same file and check yourself. This isn't graded — it's a rehearsal for the quiz, and for the next time a vendor pitches you a product and you need to work out which part of the stack it's actually replacing.

Step 2 — Pull your own Module 6 agent apart​

Four of the twelve items (6, 7, 8, and the model you configured in .env) are pieces of the exact agent you built in Module 6. Before moving on, open that lab's files again and confirm you can point to each layer in your own code:

cd ../m6
cat tools.py    # Tools & MCP layer — hand-written instead of MCP-standardized
grep -n "MAX_ITERATIONS" agent.py    # Orchestration layer — the loop's stopping condition

If you can point to the exact line that plays each role, you've internalized the stack — this lab's real goal was never the twelve labels, it was being able to do this on a codebase you didn't just read about.

Common Pitfalls​

Naming the product instead of the layer

"Claude Code" is not itself a layer — it's a host that bundles all four layers into one product. The same trap catches any agent framework or agentic IDE: the marketing name describes the whole package, not which layer of the stack it occupies. Item 11 in the exercise exists specifically to catch this.

Treating MCP as a specific tool rather than a protocol

MCP is not a product you install once — it's a shared shape that many different servers and hosts implement, the same way "REST" isn't one API. Saying "we use MCP" is like saying "we use REST": true, but it doesn't tell you which server, which tools, or which data it's actually connecting to.

Confusing short-term and long-term memory

The running conversation inside one agent run (Item 7) and a vector DB or saved file re-read across sessions (Items 3 and 12) are both "memory," but they behave completely differently — one disappears the moment the run ends, the other persists indefinitely. Module 6's context-window-vs-vector-DB distinction is the same split, just relabeled here as short-term and long-term.

Running Step 1's or Step 2's commands from the wrong directory

Step 1 assumes you're inside labs/m13/; Step 2 moves you into labs/m6/. If cat stack-map.md or cat tools.py reports No such file or directory, check which directory you're actually in with pwd, then cd back to the repo root and retry.

Teardown​

Nothing to tear down here — no processes, no environments, no cloud resources. This lab reads and writes plain text files.
