Deep Dive — The Loop That Actually Trains a Model

The lab called model.fit() and a trained model came back, instantly. Part 2 opens that one method call and shows you the actual loop running inside it: the number that measures "how wrong," and the update rule that nudges a model toward "less wrong," one small step at a time. Then it connects that loop directly to the thing you actually use every day — because "predict the next token" is this exact same loop, run on text, at a scale that makes a five-point example look like a rounding error.

Where this picks up

This page needs nothing from the lab's venv — the script below is plain Python 3 from the standard library, no packages, no network calls, nothing to configure. Run it from anywhere; re-running is always safe.

cd labs/m3

1 — What model.fit() did, one step at a time​

Analogy: picture hiking down a hill in thick fog. You can't see the bottom, and you don't have a map — but you can feel which way is downhill from exactly where you're standing right now. So you take one small step in that direction, feel again, take another step, and repeat. You'll never see the whole slope at once, but if your steps are small enough and you keep checking, you end up near the bottom anyway.

That's gradient descent. The "hill" is the loss — a single number scoring how wrong the model's current guesses are, averaged across every example. The "which way is downhill" reading is the gradient — the direction, for each of the model's internal numbers, that would make the loss worse if you moved that way, so you move the opposite way instead. One small step is one epoch: adjust every number a little, remeasure the loss, repeat.

Run the hand-written version — five points that roughly follow a straight line, fit with nothing but a loop:

python3 gradient_descent.py

Expected output

epoch    0  loss=34.0755  w=0.504  b=0.140
epoch  100  loss=0.3811  w=2.122  b=0.622
epoch  200  loss=0.3806  w=2.115  b=0.644
epoch  300  loss=0.3803  w=2.111  b=0.660
epoch  400  loss=0.3801  w=2.108  b=0.672

final   loss=0.3801  w=2.106  b=0.680

Watch the loss= value across the five printed epochs: it drops fast in the first hundred steps, then keeps inching down more slowly, the same shape you'd see on a real training run's loss curve. w and b are the two numbers the model is actually allowed to adjust — the slope and the intercept of the line it's fitting — and they crawl toward the values that best explain the five points, a little at a time, never in one jump.

scikit-learn's LinearRegression.fit() from the lab didn't loop like this — for plain linear regression there's a closed-form formula that jumps straight to the answer, so it returned instantly. But a closed-form shortcut only exists for a few simple model types. The moment a model has millions or billions of adjustable numbers instead of two, gradient descent — loop, measure loss, nudge, repeat — is the only approach that works at all, and it's what every neural network and every LLM actually runs during training.

2 — Next-token prediction is supervised learning at massive scale​

The lesson's supervised-learning example was a table of houses, each row labeled with its price. An LLM's pre-training data is built the same way — it's just built from ordinary text, cut into overlapping (input, label) pairs automatically, with no human labeling a thing:

Every sentence in the training set becomes many examples: given the words so far, the label is simply whatever word actually came next. No person sat down and tagged this data — the label was already sitting right there in the original text, one position ahead of the model's guess. That's the entire trick that lets pre-training scale to the whole internet without human labelers in the loop: the data labels itself.

The loss function is different in the details — a classification loss called cross-entropy, scoring how far off a predicted probability distribution over the vocabulary was, rather than this page's mean squared error over a number — but the shape is identical: measure how wrong, compute the gradient, nudge every parameter a tiny step, repeat. An LLM just repeats that loop across billions of parameters and trillions of tokens instead of two numbers and five points, on hardware built to run the loop in parallel across thousands of chips at once.

This is also the other half of this module's lesson on training vs. inference, made concrete: pre-training is millions of gradient-descent steps, each one changing the model's numbers a little. The moment training stops, the loop stops — inference is the forward pass only, PREDICT in the diagram above with no LOSS or GRAD after it, which is exactly why nothing you type in a chat window ever adjusts a single one of those parameters.

Where you will use this
  • A loss curve that stops dropping, or starts climbing, means the training run stopped improving. Use it when: you're fine-tuning a model (Module 5 onward) and want to know whether a stalled or rising loss is a real problem or expected noise — it's read the same way as this script's loss= column, just over many more steps.
  • Gradient descent is iterative by nature, which is why training takes hours or days while a trained model answers in milliseconds. Use it when: someone asks why "just retrain it on the fix" isn't a five-minute change — retraining re-runs this entire loop, it isn't a configuration edit.
  • Next-token prediction has no human-labeled data, only text with the labels already built in. Use it when: you're asked how a model can be pre-trained on the scale of "the whole internet" without an army of human labelers — the text itself supplies every label, one position ahead of the prediction.
