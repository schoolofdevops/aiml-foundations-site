Lab — Match the Vocabulary, Start Your Glossary

Goal: Prove you can place real product/headline snippets against the right term from the lesson, then start the personal glossary you'll keep extending for the rest of the course.

Time: ~15 minutes Prerequisites: none — this lab is reading and writing, not code. If you haven't cloned the labs repo yet, see setup/environment first.

Step 1 — Match 12 real snippets to the right term​

From the root of the course repo, open the matching exercise:

cd labs/m2
cat vocab-match.md

You'll find 12 short, real-world-style scenarios — product-page language, a billing dashboard, a support-tool description, a headline. Each one describes exactly one term from the lesson's glossary: tokens, parameters, embeddings, context window, RAG, agent, tool-calling, eval, guardrail, hallucination.

Work through all 12 before you look at the answer key. A few will feel obvious; a few are designed to make you pause — that pause is the point. Two terms (agent and hallucination) get two scenarios each, because they're the two most commonly misused words in this list, and seeing the pattern twice is what makes it stick.

Once you've written down your 12 answers, scroll to the Answer key section at the bottom of the same file and check yourself. This isn't graded — it's a rehearsal for the quiz, and for the next time a teammate says "we added an agent" and you need to know whether that's actually true.

Step 2 — Start your personal glossary​

The module title is "A Living Lexicon" for a reason: you're not just reading ten definitions once, you're starting a file you'll keep adding to. Copy the template into your own working copy:

cp glossary-template.md glossary.md

Open glossary.md and fill in both blanks for all ten terms:

  • In my own words — write the definition the way you'd explain it to a colleague, not the textbook version from the lesson. If you can't do it in a sentence or two, go back and reread that term's definition — you don't own it yet.
  • Where I've seen this — a real product page, release note, meeting, or headline where you've actually run into the word. "Not yet" is a fine answer for now.

Keep glossary.md where you can find it. Every later module in this course points back to this same file and asks you to add whatever new terms it introduces — by the capstone, it's a glossary you wrote, in your own words, not someone else's.

Why write it, not just read it

Writing a definition in your own words forces a check reading skips: if you can't rephrase it, you memorized a sentence, not a concept. That's also exactly what the quiz at the end of this module is testing — recognizing the term in a new scenario, not reciting the lesson back.

Common Pitfalls​

Confusing "context window" with "training data" or "memory"

The context window is what the model can see in this one call — your prompt, the conversation so far, anything retrieved. It has nothing to do with what the model learned during training, and it isn't persistent memory across separate conversations either. "The assistant forgot what I said" almost always means the earlier message scrolled out of the context window, not that the model was never trained on it.

Confusing "agent" with "a chatbot with a persona"

Giving a chat widget a name, an avatar, and a friendly backstory doesn't make it an agent. What makes something an agent is architectural: tools it can call, and a loop that lets it take more than one step on its own. A single-turn chat window with a persona layered on top is still a plain LLM call — Scenario 5 and 6 in the matching exercise show what actually crosses that line.

Confusing "hallucination" with "wrong because of bad data"

A model can hallucinate even when every fact in its training data was correct. Hallucination is about how the model produces an answer — generating fluent, confident-sounding text is a different skill from generating true text, and the two can come apart even on a topic the model was trained on correctly. "The training data must have been wrong" is a common but usually incorrect explanation for a confidently invented fact.

Running Step 1's or Step 2's commands from the wrong directory

Both commands assume you're inside labs/m2/. If cat vocab-match.md or cp glossary-template.md glossary.md reports No such file or directory, run cd labs/m2 from the repo root first, then retry.

Teardown​

Nothing to tear down here — no processes, no environments, no cloud resources. This lab reads and writes plain text files. Keep labs/m2/glossary.md; you'll open it again in every module from here on.
