Where does ChatGPT actually fit?​

You use AI products every day — a chat assistant, a code completion tool, a fraud alert on your bank statement, a recommendation feed. If someone asked you in a review or a vendor call "is that machine learning, or is it a language model, or is it an agent?" — could you answer without hedging? Most technical professionals can't, and it's not because the ideas are hard. It's because nobody ever drew the boundaries. This module draws them.

By the end of this lesson you'll be able to place ChatGPT, Claude, a fraud-detection model, and a research agent on one map — and know exactly which question to ask about each one.

The map is nested, not a list​

Analogy: Think about how you'd describe your own job to someone outside tech. You wouldn't say "I do computers" — that tells them nothing. You'd narrow it: "technology" → "software engineering" → "backend infrastructure" → maybe "the payments team." Each word is a real, correct answer, just at a different zoom level. Nobody is wrong; they're standing at different distances from the same building.

The AI field works exactly the same way. "AI," "machine learning," "deep learning," and "LLM" are not four different technologies competing for the same job — they're four zoom levels on the same building, each one narrower and more specific than the last.

  • Artificial Intelligence is the widest circle: the goal of getting a machine to do something that looks like it requires judgment. It's a goal, not a method — a rule-based tax calculator, a chess engine's search tree, and ChatGPT are all "AI" by this definition, even though almost nothing else about them is similar.
  • Machine Learning is one method inside that circle: instead of an engineer hand-writing the rules ("if the email contains these 40 words, mark it spam"), you show the system thousands of labeled examples and let it find the pattern itself. The rules come from data, not from a developer's if/else tree.
  • Deep Learning is one technique inside ML: instead of a single, simple function, you stack many layers of small transformations on top of each other — a "neural network" — so the system can learn patterns in messy, high-dimensional data like pixels, audio, or raw text that simpler ML methods handle poorly.
  • Large Language Models are one specific product of deep learning: a network trained on enormous amounts of text to do one narrow thing extremely well — predict the next chunk of text given everything before it. Do that at scale, on the whole internet, and the result can answer questions, write code, and hold a conversation.
  • Agents sit outside this nesting, not inside it. An agent is not a smarter model — it's an architecture: an LLM wrapped with tools it can call, memory it can read and write, and a loop that lets it take more than one step before handing control back to you.

ChatGPT's raw text generation lives in the LLM region. The moment it browses the web, runs code, or checks your calendar across several steps to complete a task, you've crossed into the agent region — same underlying model, different architecture wrapped around it. Claude, Gemini, and GPT-5-class models all live in the LLM region; Claude Code, a research assistant that searches and summarizes, or a support bot that files a ticket on your behalf, live in the agent region because of what wraps the model, not because the model itself changed.

Why this map matters more than it looks like it should

The four regions don't just organize trivia — they change the questions you ask. "How was it trained, and on what data?" is an ML/DL question. "How many tokens am I paying for, and what's in the context window?" is an LLM question. "What tools can it call, and what happens if it calls the wrong one?" is an agent question. Ask an ML question about an agent and you'll miss the risk that actually bites you.

One more label you'll need: RAG​

Before you test yourself, one more term belongs on the map — not as a new region, but as a pattern layered onto the LLM or agent regions: RAG (retrieval-augmented generation). A plain LLM only knows what was in its training data. RAG looks up relevant text from a source you control — your documents, your product's help pages — right before generating an answer, so the response is grounded in something real instead of only what the model memorized. You'll classify scenarios that use it in a moment, and you'll build a small RAG pipeline yourself in Module 6.

The vendor-call test​

Here's where this stops being trivia. Say your team is reviewing three vendor pitches this quarter: one sells "AI-powered anomaly detection," one sells "an LLM copilot for your support team," and one sells "an autonomous agent that resolves tickets end to end." All three say "AI." If you can't place each on the map, you ask the same generic question of all three and learn nothing. If you can, you know exactly what to ask:

  • The anomaly-detection pitch is almost certainly classical ML — ask about training data, retraining cadence, and false-positive rate.
  • The copilot is an LLM sitting in a chat window — ask about the context window, hallucination rate, and what happens when it doesn't know something.
  • The end-to-end resolver is an agent — ask what tools it can call, what happens when it calls the wrong one, and who's accountable when it acts on bad information.

Same word, "AI," three completely different sets of risks. The map is what lets you tell them apart in the room, not after the postmortem.

This is not new — but it is now unavoidable

None of these four ideas is new; supervised learning is decades old and neural networks older still. What's new is that all four now show up in the same product, sometimes the same feature, and a technical professional who can't place them apart gets stuck asking the wrong question in every AI conversation at work. That's the gap this module closes.

The four projects you'll build​

This course is not four modules of theory followed by a project — it's one growing project, built one capability at a time, starting in the next few modules:

  1. A predictor — a classical ML model that forecasts a number from historical data (Module 3).
  2. A digit classifier — a small neural network, so you feel deep learning working, not just read about it (Module 4).
  3. An LLM-powered tool — your first real API call to a language model, wired into a small command-line tool (Module 5, and you'll take the very first step toward it in today's lab).
  4. An autonomous agent — a system that reasons in steps and calls tools on its own to research and summarize real information (Module 6). This is the course's marquee moment: you will watch a finished agent run live before you build your own.

By the capstone (Module 9), all four converge into one assistant — an LLM core, an agent loop, retrieval over a PDF you choose, and an API you can call like a real client. You run it, you break it on purpose, and you walk away with something worth demoing.

What's next​

Now that you have the map, Module 2 gives you the vocabulary that goes with it — tokens, embeddings, context windows, RAG, agents, hallucination — so the next AI headline or product page reads as words you actually know, not noise.
