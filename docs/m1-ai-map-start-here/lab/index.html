Lab — Spot the AI, then talk to a real model

Goal: Verify your lab environment, classify five real scenarios against the map from the lesson, then make a real API call to a real model and print a real response — the moment this whole course is building toward starting today, not in Module 5.

Time: ~20 minutes Prerequisites: none beyond what Step 1 verifies. If you're going the Ollama route, you'll install it in Step 3.

Step 1 — Verify your lab environment​

Confirm the tools this course assumes are on your machine.

python3 --version

Expected output (exact patch version will vary by machine)

Python 3.13.7

You need Python 3.10 or newer. If you see 3.9 or older, upgrade before continuing — see setup/prerequisites for OS-specific install commands.

python3 -m pip --version

Expected output (exact version numbers and path will vary by machine)

git --version

Expected output (exact version will vary by machine)

curl --version

Step 2 — Create the venv and install the client library​

Every module's lab lives in its own folder under labs/ in the course repo. If you haven't cloned it yet, see setup/environment first. From the root of the course repo (where you cloned aiml-foundations-labs):

cd labs/m1
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

requirements.txt pulls in one package: openai. You'll use it as a generic OpenAI-compatible client, not because you're necessarily calling OpenAI — Ollama, Gemini, Grok, and Claude all speak the same request/response shape, so one small library works against all of them.

Step 3 — Configure a free provider​

Pick one of the two $0 paths below. Both work identically with the script in Step 5 — only the environment variables change.

Option A — Local Ollama (no signup, no API key)​

Install Ollama if you don't have it yet:

# macOS
brew install ollama
# Linux
curl -fsSL https://ollama.com/install.sh | sh

Start it and pull a small model:

ollama serve &
ollama pull qwen2.5:1.5b

If Ollama is already running as a background service (common if you installed the desktop app), the first line will print Error: listen tcp 127.0.0.1:11434: bind: address already in use. That's harmless — it just means the server is already up — ignore it and let ollama pull continue.

Expected output (a live progress bar while pulling; instant success if the model is already present, as it is once you've pulled it the first time)

pulling manifest
pulling 183715c43589: 100% ▕██████████████████▏ 986 MB
pulling 66b9ea09bd5b: 100% ▕██████████████████▏   68 B
pulling eb4402837c78: 100% ▕██████████████████▏  1.5 KB
pulling 832dd9e00a68: 100% ▕██████████████████▏   11 KB

success

That's it — first_call.py defaults to http://localhost:11434/v1 with model qwen2.5:1.5b, so you don't need to set anything else for this option.

Option B — Google Gemini free tier (needs a free API key)​

Grab a free key at aistudio.google.com/apikey, then:

cp .env.example .env

Open .env, uncomment the Option B — Google Gemini block, paste your key in, save, then load it:

source .env
OpenAI, Grok, and Claude work the same way

.env.example includes commented-out blocks for OpenAI, xAI Grok, and Anthropic Claude too. Every provider in this course is reached through the same three environment variables — LLM_BASE_URL, LLM_API_KEY, LLM_MODEL — so switching providers later is a config change, not a code change.

Step 4 — Spot the AI (warm-up)​

Before you call a model, spend five minutes classifying five short scenarios using the map from the lesson. Open labs/m1/spot-the-ai.md:

cat spot-the-ai.md

Read each scenario and decide: ML, LLM, RAG, or Agent? Then scroll to the answer key at the bottom of the same file and check yourself. This isn't graded — it's a rehearsal for the quiz, and for the next time someone in a meeting says "we're adding AI" and you need to know which kind.

Step 5 — Your first LLM call​

This is the payoff. Run the script:

python3 first_call.py

Expected output (a real, generated sentence — the exact wording will differ every time you run this; here are two actual captured runs against local Ollama / qwen2.5:1.5b to show that variance)

A large language model generates responses based on text input, while machine learning enables systems to learn from data and make predictions or decisions without explicit programming instructions.
Machine Learning involves algorithms that allow machines to learn from data without being explicitly programmed, while a Large Language Model processes text inputs directly using neural networks to generate human-like responses.

You should see one sentence of real, generated text answering "what's the difference between machine learning and a large language model?" — the exact wording will vary between runs and between providers; that variability is itself a property of generative models worth noticing.

Open the file and look at what actually ran:

cat first_call.py

Three lines do the real work — everything else is reading configuration:

LineWhat it does
client = OpenAI(base_url=..., api_key=...)Point the client at whichever provider's endpoint you configured in Step 3
response = client.chat.completions.create(model=..., messages=[...])Send the prompt, get a structured response back
print(response.choices[0].message.content)Pull the generated text out of the response and print it

You just made the same call — the same three lines — that every LLM-powered product you use is built on top of. Everything from Module 5 onward extends this exact call: more messages, tools, retrieved context, an agent loop. Right now, you've proven the wiring works.

Common Pitfalls​

python3: command not found or version below 3.10

Some systems ship python (no 3) or an old default. Check with python3 --version; if it's missing or too old, install 3.10+ per setup/prerequisites rather than fighting the system Python.

pip install succeeds but python3 first_call.py still says ModuleNotFoundError: openai

Your venv isn't active. pip install -r requirements.txt installed into whatever Python was active at the time — if that was your system Python, the package isn't where your venv looks. Run source .venv/bin/activate again (you'll see (.venv) in your prompt) and re-run the install.

AuthenticationError or 401 from the API

Your LLM_API_KEY is missing, invalid, or wasn't actually loaded into the shell. If you edited .env, confirm you ran source .env in the same terminal you're running the script from — source only affects the current shell session, not new tabs or windows.

Connection refused on localhost:11434

Ollama isn't running. Start it with ollama serve (or check it's running as a background service), then confirm:

curl http://localhost:11434/api/tags
model "qwen2.5:1.5b" not found

You configured Ollama but never pulled the model. Run ollama pull qwen2.5:1.5b and try again.

Wrong base_url for your chosen provider

Every provider expects a slightly different base URL, and getting it wrong usually shows up as a 404 rather than an obviously helpful error. Double-check the exact URL against the block you uncommented in .env.example — a trailing /v1 or missing /openai/ segment is the usual culprit.

Teardown​

deactivate

There's nothing else to tear down — no containers, no cloud resources. If you used Ollama, you can leave it running (later modules use it too) or stop it with pkill ollama if you'd rather reclaim the RAM. If you created a .env file with a real API key in it, don't commit it — it's already covered by the course repo's .gitignore.
