Frontier — Your Three Paths: MLOps, LLMOps & Agentic DevOps

What do you want to be good at a year from now?​

Nine modules ago you hadn't called an LLM from your own code, built an agent, retrieved from a PDF, or served a model behind an API. Now you've done all four, and Module 9 wired them into one assistant you can run, break, and show someone. Module 10 recapped what you built and put the three paths ahead of you side by side as a reference card. This module does something narrower and more useful: it asks you to actually choose one, with a real rationale instead of a coin flip.

Three follow-on courses pick up exactly where this one stops. None of them re-teach what you just learned — each one takes a different slice of it and goes deep. This lesson lays the three out honestly, including what's genuinely hard about each one, so the choice you make in today's lab is informed, not guessed.

Three engineers, three different pages​

Analogy: picture three engineers who all went through the same foundations training you just finished. Six months later, each of them is getting paged for a different reason. One gets pulled in because a fraud-detection model's approval rate has been quietly drifting for two weeks and nobody caught it until finance noticed the numbers looked off — that's a model-and-data problem, and fixing it for good means owning retraining pipelines and drift monitoring, not just retraining once by hand. The second gets pulled in because a support chatbot confidently quoted a price that hasn't been correct in months — the model didn't change, but the retrieved content behind it went stale and nothing caught that before a customer did. The third gets pulled in because an agent that was supposed to file low-risk tickets on its own instead tried to close a customer's account without anyone approving the step — the model reasoned exactly as designed, but nothing in the system stopped it from acting on that reasoning.

Same foundation, three different failure modes, three different jobs. That's the honest version of "MLOps vs. LLMOps vs. Agentic DevOps" — not three abstract categories, but three different things that break and three different skill sets for catching them before a customer does.

The three paths, side by side​

MLOps — the model itself​

You already met this discipline by name in Module 8: versioning data and model weights, automating retraining, watching for drift instead of just watching for crashes. The MLOps path takes that map and turns it into hands: you build the actual retraining pipeline, the model registry, and the drift-triggered alerts that Module 8 only described. It builds most directly on Module 3 and Module 4 — the two labs where you trained a model yourself from data you controlled — plus Module 7's serving pattern and Module 8's monitoring map. This is the path if the fraud-detection scenario above is the one that made you want to open a terminal, not the one that made you want to change teams.

LLMOps — the prompt, the context, and what it costs​

Once Module 5 had you call a model someone else trained, what you actually controlled shifted from weights to prompts, retrieved context, and cost per call. The LLMOps path goes deep on operating that: eval suites that grade an answer instead of pass/fail, RAG pipelines that need their own freshness checks so retrieved content doesn't go stale the way it did in the chatbot scenario above, and the latency/cost tradeoffs that show up the moment an LLM call is running in front of real traffic instead of your terminal. It builds most directly on Module 5's LLM call, Module 6's RAG pipeline, and Module 7/8's serving and eval-suite material. This is the path if the second scenario above is the one you recognized from your own team's chat.

Agentic DevOps — the loop, the tools, and who's allowed to act​

Module 6 gave you an agent that decides its own next step across tool calls, and Module 8 named the discipline that watches that loop in production: AgenticAIOps, also called AgenticOps — step counts, tool failures, runaway loops. The Agentic DevOps path is broader than operating one agent: it's building and governing systems where agents take real actions against real infrastructure, which means everything AgenticAIOps watches for, plus the governance question the account-closing scenario above raises — which actions does an agent get to take unsupervised, and which ones require a human in the loop. It builds most directly on Module 6's agent loop and tool-calling, Module 8's agentic observability section, and Frontier · The Agent Ecosystem (MCP, tool ecosystems, agentic IDEs) from this same track. This is the path if the third scenario is the one that worries you the most — in a good way.

Where this course's spine points from here​

Read it the same way Module 8's discipline diagram read: each path doesn't discard what you built — it takes one part of the assistant you already have and goes deep on operating and building more of exactly that part, at production scale, on systems that don't get torn down after an hour.

Choosing now doesn't lock you in​

One honest note before the lab: picking a path today is a starting point, not a contract. Plenty of engineers end up doing real work across two of these three within the same year, because a production system rarely stays inside one row of that table — Module 8 made the same point about Module 9's capstone, which needs all three disciplines layered together. What matters today isn't picking the "correct" answer. It's picking the one you have an honest reason to start with, so your next course isn't a repeat of foundations you've already done, and isn't a leap past fundamentals you still need.

What's next​

That's the whole map: three paths, three different things that break, three different jobs, and a clear line from each one back to the labs you already ran. The lab is a short, personal worksheet — no code, no terminal — where you turn this into your own answer and a plan for the next six months.

You built a real, working AI assistant across this course: a model that predicts, a model that classifies, an LLM you called yourself, an agent that reasons over tools, a RAG pipeline grounded in your own document, and all of it served behind an API you can hit with curl. That's genuinely a lot, and it's genuinely yours. Whichever path you pick next, you're not starting from zero — you're starting from here.
