Lab — Field-Scan Five Developments, Extend Your Glossary

Goal: Practice the triage habit from the lesson on five fresh scenarios, then add this module's new vocabulary to the living glossary you started in Module 2.

Time: ~15 minutes Prerequisites: Module 2's lab (you should already have labs/m2/glossary.md). No code, no lab environment tools — this is reading and writing, the same format as Module 2's lab.

Evergreen exercise

The five scenarios below are illustrative snapshots of what GenAI headlines looked like around mid-2026, not a permanent list. Revisit this same exercise later with whatever's actually in the news then — the two triage questions from the lesson don't expire even when the examples do.

Step 1 — Field-scan five scenarios​

From the root of the course repo, open the field-scan exercise:

cd labs/m11
cat field-scan.md

You'll find five short, release-note-style scenarios. For each one, fill in two blanks using the word banks at the top of the file:

  • Type — which of the five recurring shapes from the lesson it is: reasoning models, multimodal-native models, open-weight vs frontier, agentic tool-use / standardized tooling, or falling cost per token.
  • Impact — what kind of impact it has on you as a builder: new capability, cost/access shift, trust/eval shift, or ecosystem/tooling shift.

Work through all five before checking the answer key at the bottom of the same file. The key adds a third column — which AI-Map region (from Module 1) each development actually lands in — and that's the part worth sitting with: four of the five scenarios are LLM-region news, even though all five would get called "AI breakthroughs" in a headline.

Step 2 — Extend your Module 2 glossary​

This module introduces six new terms. Open the additions file:

cat glossary-additions.md

Copy each of the six headings into your own labs/m2/glossary.md (the file you started in Module 2), fill in both blanks — In my own words and Where I've seen this — the same way you did there, then add a line to that file's "Extended in" tracker at the bottom:

Extended in: Module 2 (this module). Module 11 — reasoning model, multimodal-native model,
open-weight model, frontier model, tool-use protocol, inference cost.

If you can't write a one-sentence definition for one of the six terms without looking back at the lesson, that's the signal to reread that term's paragraph in the landscape section — same rule as Module 2.

Why this stays in one file instead of a new one per module

A glossary scattered across ten separate files is one you'll never reread. Keeping every term in the same glossary.md, extended module by module, is what makes it a reference you'll actually reach for months later — during a vendor call, a design review, or the next headline that lands in your inbox.

Common Pitfalls​

Treating "reasoning model" as the same thing as "agent"

A model that visibly thinks through steps before answering is still a single call with a single input and a single output — no tool use, no multi-step loop, no handoff back to you mid-task. The lesson's "Reasoning models are not agents" section is the one learners most often skip and then get wrong on the quiz — reread it if Scenario 1 didn't feel obvious.

Assuming every headline is a "new capability"

The answer key shows two scenarios (open-weight vs. frontier, and falling cost per token) landing on the same impact type: cost/access shift. That's the most common outcome of a real field scan, not a rare one — most releases make something that already existed cheaper or more available, rather than making something genuinely new possible. Don't inflate a price cut into a breakthrough.

Running Step 1's or Step 2's commands from the wrong directory

Both commands assume you're inside labs/m11/. If cat field-scan.md or cat glossary-additions.md reports No such file or directory, run cd labs/m11 from the repo root first, then retry.

Teardown​

Nothing to tear down — no processes, no environments, no cloud resources. This lab reads and writes plain text files. Keep your updated labs/m2/glossary.md; later modules keep pointing back to it.
